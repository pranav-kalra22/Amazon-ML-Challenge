# Blocking Benchmark

## Goal
Evaluate candidate-generation algorithms independently of downstream ML matching classifiers. Ensure high candidate recall ceiling ($>99.5\%$) while keeping candidate pair volume computationally scalable.

## When to Use
- When creating or modifying blocking rules, inverted indices, or hashing functions.
- To audit the recall upper bound of the entire end-to-end pipeline.
- Before generating `candidate_pairs.tsv`.

## Required Inputs
- Ground Truth mapping on validation split: `{s1_id: set(matched_ids)}`
- Candidate pairs generated by blocker: `{s1_id: set(candidate_ids)}`
- Total potential search space size ($N_{S1} \times (N_{S2} + N_{S3})$).

## Metrics to Compute & Report
For every blocker evaluated, measure:
1. **True-Link Recall**:
   $$\text{Recall}_{\text{links}} = \frac{\sum_i |T_i \cap C_i|}{\sum_i |T_i|}$$
2. **Full-Entity Coverage**:
   Fraction of non-singleton S1 entities where $100\%$ of true matches were captured in candidates ($T_i \subseteq C_i$).
3. **Candidate Distribution per S1**:
   - Mean candidate count
   - Median (p50)
   - 90th percentile (p90)
   - 95th percentile (p95)
   - 99th percentile (p99)
   - Maximum candidate count
4. **Total Candidate Pairs**:
   Total number of generated candidate pairs across all S1 entities.
5. **Reduction Ratio**:
   $$RR = 1 - \frac{\text{Total Candidate Pairs}}{N_{S1} \times (N_{S2} + N_{S3})}$$
6. **Oracle Candidate-Ceiling Macro $F_{0.5}$**:
   Score obtained if an imaginary perfect classifier perfectly selected all true matches that exist in the candidate set ($P_i = T_i \cap C_i$).

## Procedure
1. Run candidate generation on the defined validation split.
2. Calculate all 6 primary metrics listed above.
3. Isolate all missed true links ($T_i \setminus C_i$) and export to `reports/blocking/<blocker_name>_missed_links.csv` for inspection.
4. Compare against the incumbent best blocker.
5. Log metrics into `experiments/experiment_log.csv`.

## Required Outputs
- Diagnostic markdown summary under `reports/blocking/`.
- Exported error analysis file: `reports/blocking/<blocker_name>_missed_links.csv`.

## Core Principles & Constraints
- **Recall Ceiling Comes First**: A blocker is NEVER "better" simply because it produces fewer candidates if its true-link recall drops.
- **Auditable Candidate Sets**: All candidates must follow the official formatting rules (S2 and S3 IDs only, no duplicates).
